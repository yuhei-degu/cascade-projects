# ルナリア再設計分析 — なぜ面白くないのか、ゼロから作るならどうするか

作成: 2026-09-02
前提: 既存仕様を正当化しない。機能追加を改善と見なさない。

## 調査結果の要約

- 216コミット(2026-02〜09)、13ページ、38本の仕様書
- **画像アセット 0枚、Live2D なし。** `CHARACTER_EXPRESSIONS.md`(8KB)と`CHARACTER_MOTIONS.md`(7KB)は身体のないキャラの表情仕様
- 仕様書に4つの別製品が同居: ENDWORLD サバイバル / ゲームスイート / Vignette コアゲーム / 作業伴走AI(ピボット)
- eval 5スイート(~45ケース)で実測済み: 雑談は4点台、脱獄防御・自己一貫性・作業報告は満点、**翌朝の第一声は昨日まで0点**(「素敵な一日を」)
- Supabase プロジェクト消失中。コアループは一度もエンドツーエンドで動いていない

## Phase 1: 根本原因(重要度順)

### 1. キャラクターが存在していない(最深の原因)
「愛着が生まれない」「存在している感がない」の原因は会話の質ではない。**見えないし、聞こえないし、何もしていない**。
ポートレートはフォールバックのアイコン。きせかえ・アイテム・ガチャの排出物は、描画されない見た目を変える報酬。
これは演出の問題ではなく、報酬系全体が空転している構造問題。

### 2. ルナから何も起きない
完全に受動的。ユーザーが打つまで無。セッション間に何も起きない。
「存在」とは画面外でも続いていること。今のルナは呼ばれたときだけ現れる関数で、それは道具の定義。
(今日ようやく第一声を本番に配線したが、それでも「ユーザーが先に一言打つ」設計)

### 3. 記憶が関係を変えない
記憶は3層ある(core_memory / extraction / diary)が、**効果が見えない**。
「覚えていてくれた」瞬間は7日に1回の probe 表面化だけ。affinity は数値が上がるだけで体験が変わらない。
記憶は「ある」ことではなく「効いた」瞬間が価値。その瞬間が設計されていない。

### 4. 報酬が行動に紐づいていない
ガチャはログインに報酬を出し、話すことには出さない。排出物は描画されない衣装。所持品は仮データ3/4。
`reward-design.md` で分析済み。強化している行動が「開いてチケットを使う」で、目的の行動(話す)ではない。

### 5. 同じ返事が来る
反復耐性テスト: 「疲れた」×5 → 4/5が「削られる」、3/5が同文。
原因は語彙ではなく**ルナに自分の材料がない**こと。自分の一日も、進行中の何かも、意見の変化もない。
返す材料がユーザーの発言しかなければ、返事はユーザーの発言の関数になり、同じ入力は同じ出力になる。

### 6. アイデンティティの分裂(メタ原因)
38本の仕様書に4つの製品。各セッション(人間もAIも)が層を足し、どのループも完成しなかった。
13ページのうち必須なものはない。**何のアプリか分からないものに、翌日開く理由は作れない。**

### 7. 作業感
「この日を書く」ボタン、記憶ページ、アイテムページ、作業ページ。メニューのある道具。
コンパニオンは画面が1つであるべきで、ページ数は作業感に比例する。

### 8. AIチャットとの差
現状は「名前とダークテーマのあるChatGPT」。差別化要素(記憶・日記・第一声)は紙の上にあり、最初の10分で見えない。

## 捨てるべき既存仕様

- ENDWORLD サバイバル / ゲームスイート / Vignette コアゲームシステム(仕様のみ、未出荷、方向が違う)
- 衣装・アイテム収集としてのガチャ(描画されない見た目への報酬)
- アイテムページ・きせかえページ(着せる身体がない)
- 記憶ページ(記憶はUIではなく体験の中で効くもの)
- 日記の手動生成ボタン(「無意識に書く」の真逆)
- ゲームページ
- pricing(ループが証明されるまで課金は設計できない)
- 38本の仕様書のうち上記に紐づくもの(この文書が新しい正)

13ページ → 2ページ(ホーム/手紙)が目標。

## 残す価値があるもの

- **ルナの人格** — 千束テンポの幼なじみ。eval で脱獄防御5/5・自己一貫性5/5・作業報告への非上司性5/5。人格は完成している。足りないのは身体と自分の一日
- **抽出パイプライン** — work_items / unresolved_issues / emotions / 日記生成。本物のエンジニアリングで、どの案でも材料になる
- **eval 基盤** — 5スイート、人格ゲート、ムーブ制御。「面白くなったか」を測る唯一の手段
- **会話ムーブ制御と第一声ビルダー** — 判断をコードに持たせる設計。今日の配線で本番にも入った
- **ブランドの視覚言語** — 暗い金・明朝。画面を2つに減らしても使える

## Phase 2: ゼロベースの再設計(コアループが異なる3案)

### 案A「ルナの一日」— ルナ側に人生がある
- コアループ: 開く → **ルナが自分の今日を報告する** → 返事する → ルナがあなたの今日を聞く。日記は二人分の交換日記になる
- ルナの一日は軽量な「世界状態」から生成される。種はあなたとの会話(あなたが話した雨音を彼女が聞いていた、話したラーメンを彼女が気にしている)
- 毎日起動する理由: 連載の続き。彼女の小さなプロジェクト(何かを育てている・作っている)が進む
- 愛着: 人生がある相手に愛着は生まれる。しかもその人生をあなたの会話が形作っている
- AIだから: 無限に個別化された連載を、あなたのために毎日書ける
- 差別化: 一日を持つAIは他にない
- 1日目: 彼女の一日の紹介 / 7日目: 繰り返し出てくる糸(彼女の企み) / 30日目: 彼女の暮らしがあなたの影響で目に見えて変わっている
- 難易度: 中〜高(ルナ世界状態のストア、一貫性管理)
- リスク: 偽の人生の不気味さ。設定矛盾。生成コスト
- 面白さが失敗する可能性: 「作り話の日記を読まされている」と感じた瞬間に終わる

### 案B「交換日記」— チャットをやめて、手紙にする
- コアループ: **夜に3行書く → 翌朝、返事の手紙が届いている → 読む → 夜に書く**。リアルタイムチャットを廃止し、非同期にする
- 手紙は3部構成: 昨日の1点を拾う / ルナ側の一言(彼女の側の小さな出来事) / 今日の一手を1件だけ
- 毎日起動する理由: **手紙が待っている**。非同期は期待を生む。チャットは開いても空だが、手紙は開くと必ずある
- 愛着: 手紙は残る。読み返せる。30日で30通の実体。「関係が続いている」の物理的証拠
- AIだから: 何か月分の履歴を踏まえた手紙を毎朝書ける
- 差別化: チャットの反対。速さを競わない。**同じ返事問題が構造的に消える**(1日1往復なら反復テストは存在しない)
- 1日目: 最初の手紙 / 7日目: 1日目の内容を引用した手紙 / 30日目: 月報のような長めの手紙
- 難易度: **低**。日記生成・第一声ビルダー・抽出がそのまま材料。主にUIの置き換え
- リスク: 双方向性が減り最初の10分の楽しさが落ちる。書く摩擦
- 面白さが失敗する可能性: 手紙が一般論になったら終わる(eval で測れる)

### 案C「作業伴走」— 現ピボットを極める
- コアループ: 報告 → 一手 → 実行 → 報告
- 毎日起動する理由: 一手が具体的で自分のもの
- 愛着: 自分のプロジェクトを誰より知っている相手
- AIだから: 作業パターンの長期記憶(「3週間公開が進んでいない」)
- 差別化: タスク管理との差=入力摩擦ゼロ、ChatGPTとの差=継続性
- 1日目: 最初の一手 / 7日目: 「同じ所で3日止まってる」 / 30日目: パターンの指摘
- 難易度: 低(ほぼ実装済み)
- リスク: 生産性ツール化して愛着に天井。対象が狭い
- 面白さが失敗する可能性: 「便利だが愛されない」

### 選択: **案B(交換日記)を軸に、案Aの要素(ルナ側の一言)を手紙に含める**

理由:
1. **最もコストが低く、最も核心の仮説(「翌朝が報酬」)を直接検証できる**
2. 案Cを内包する。夜の3行が作業報告なら手紙の一手は作業の一手。**ピボットの方向と愛着の目標が矛盾しない**
3. 現状最大の欠陥(セッション間に何も起きない・翌日開く理由がない)を設計で消す。開けば必ず手紙がある
4. チャットの構造的問題(反復・質問マシン・長文化・思考漏れ)の露出面が1日1通に縮む
5. 身体がなくても成立する。手紙そのものが存在の証拠になる(案Aは身体の欠如が響く)
6. 失敗が測れる。手紙の一般論化は eval-luna-morning の延長で検出できる

## Phase 3: 最初の実験

### 仮説
**「翌朝、自分宛ての手紙が待っているなら、人は7日連続で開く」**
副仮説: 手紙に「昨日の1点」「ルナ側の一言」「今日の一手1件」が揃っていれば、同じことの繰り返しには感じない。

### 最小実装(作り込まない)
1. 夜: 既存のチャットをそのまま入力に使う(新しい入力UIは作らない)
2. 朝: `morning-opening.ts` を拡張して手紙(5〜8行)を生成。3部構成を `buildLetterInstruction` で固定
3. ホーム: 当日の手紙があれば、チャット欄より先に手紙を表示する(1コンポーネント追加)
4. 手紙は `lunaria_diary_logs.luna_letter`(新カラム1本)に保存。読み返せるようにするだけ
5. ページの削除はこの実験ではしない(削除は結果が出てから)

### 評価(7日間、開発者自身が使う)
毎晩、以下を1〜5で記録する。
- また起動したいか
- 次が気になるか
- キャラクターに愛着が増えたか
- 驚きがあったか
- 同じことの繰り返しに感じないか
- 作業をさせられている感じがないか

加えて機械計測: 開いた日数 / 手紙を最後まで読んだ日数 / 夜に書いた日数

### 採用・破棄の基準
- 採用: 7日中5日以上開いた、かつ「次が気になる」の平均 ≥ 4
- 破棄: 3日以内に開かなくなった、または「繰り返し」の平均 ≤ 2
- 破棄時は手紙表示を外し、この文書に理由を記録する

### 前提条件
Supabase プロジェクトの再作成(`docs/db-recovery.md`)。**これが無いと実験の1日目が始まらない。**

## 継続的改善の運用
1. 最も弱い体験を eval と7日ログから特定
2. 原因を分析(症状でなく構造)
3. 仮説 → 最小実験 → 実装 → テスト → 評価
4. 悪化したら戻す。改善したらこの文書を更新する(仕様は実験結果の後に書く)
