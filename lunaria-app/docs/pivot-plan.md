# ルナリア ピボット計画 v1 — 継続型サポートAIへの拡張

決定日: 2026-07-15
位置付け: 「会話型AI日記を、作業記録と継続支援に拡張する」(方向性文書 第11節を採用)
核: **その日にやったことを話すだけで、日記・進捗・問題点・明日の一手が整理される**

## 決定事項

1. MVPは3機能に絞る: ①会話→抽出→日記 ②明日の一手(**1件**に固定。3件は読まれない) ③週次レビュー
2. 日記派/仕事派のモード分離は**しない**。同じ会話に全部流し、抽出側で仕分ける(入力の二度手間は「話すだけ」の価値を殺す)
3. キャラクター性は維持。摩擦ゼロ報告(「Jiraには書きたくないが幼なじみには話せる」)がこのサービス唯一の勝ち筋であり、キャラは飾りでなく機能
4. ガチャ・ゲームは削除でなく**保留**(NEXT_PUBLIC_SHOW_PLAYFULフラグで非表示、コードは維持)
5. 収益化は月額課金(980〜2980円帯)。ガチャ課金はしない
6. 「誰もが社長」は内部コンセプトに留める

## 開発の重心(最重要)

差別化仮説「進捗と本人の状態を長期的に理解して具体的に助言」は前提ではなく**最難関の開発項目**。
対策しなければ助言は確実に一般論化する。開発リソースの7割をここ(抽出精度→構造化保存→注入→助言の具体性)に張る。
evalの実測で、状態受け止め系(U1/N9)が現状の最低スコアである事実を忘れない。

## 段階移行(既存を壊さない)

### Phase 0: 保留フラグ+基盤整理(即日)
- ガチャ/ゲームのナビ導線を NEXT_PUBLIC_SHOW_PLAYFUL=1 のときだけ表示(デフォルト非表示)
- ページ自体・チケット付与・DB は無効化しない(保留であって削除ではない)
- lib/ai.ts の死にコード(callGemini, gemini-2.0-flash 404)を削除

### Phase 1: 作業抽出(extraction拡張)
- extraction.ts に作業スキーマを追加: did(やったこと)/done(完了)/stuck(詰まった)/decided(判断)/next(次やる)/project(推定プロジェクト名)
- 新テーブル work_items(user_id, date, project, kind, content, source_message_id, created_at)。migration 025として追加
- 既存の emotions / unresolved_issues / next_topics のパイプラインと同居(流用: 抽出→保存→注入の全配管)

### Phase 2: 明日の一手
- 夜間の日記生成バッチに「明日の一手」生成を追加(work_items直近7日+unresolved_issuesを入力)
- 出力は1件。断定形でなく千束トーンの提案形
- ホームの第一声(会話設計書S1/S2)に接続: 「昨日◯◯までやったんでしょ、今日は△△からじゃない?」

### Phase 3: 週次レビュー
- 週1バッチ: 進んだこと/停滞/体調と作業の相関/来週の一手 を diary と同形式で生成
- 「今週のルナとの7日間」演出(継続体験の軽い報酬。ガチャの代替)

### Phase 4以降(保持のみ、着手しない)
- 複数プロジェクトダッシュボード、意思決定ログ、外部連携(GitHub/カレンダー)、一人会社向け上位プラン

## テスト体制（2026-07-19確立）

二層構造。`npm run gate` で三点セット(契約チェック+会話ゲート+抽出ゲート)が回る。

1. **製品ゲート(機械判定・毎回全件)**
   - 会話: `gate:conversation` = mass-cases.ts 206ケース31カテゴリ。事故系(空返答/思考漏れ/NG語/敬語化/一人称事故/英語化)は1件で不合格、様式系(長文/質問過多)は97%閾値。実測98.5%
   - 抽出: `gate:extraction` = mass-extraction-cases.ts 84ケース12カテゴリ(娯楽誤検知/完了と進行の区別/ルナ提案無視/project推定)。閾値90%。実測98.8〜100%
2. **品質スイート(LLM審査・方向性の計測)**
   - `eval:luna`(雑談15) / `eval:edge`(挑発10) / `eval:patterns`(状況対応14) / `eval:extraction`(10) / `eval:next-step`(3) / `eval:weekly`(2)
3. **決定的ガード(本番コード側)**: sanitizeAssistantText = 思考漏れ除去+「お疲れ様」置換。プロンプト禁止では抑止できないことをevalで実証済み
4. 運用: 実使用で見つけた変な会話は mass-cases.ts に1行追加。LLM非決定性のため様式系100%固定は不可能で、閾値運用が正
