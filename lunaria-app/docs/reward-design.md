# 報酬設計 v1 — ガチャの役割を差し替える

決定日: 2026-07-26
結論: **機構としてのガチャは残す。コンテンツとしてのガチャ(衣装・アイテム収集)は課金から外す。**

## なぜ今のガチャが噛み合わないか

報酬が「アプリを開いてチケットを使うこと」に付いていて、「その日のことを話すこと」に付いていない。
強化したい行動は報告であって、ガチャを回すことではない。
さらに報酬が引いた瞬間に完結するため、本来の報酬である「翌朝の一手」と競合する。
安いほうの報酬があると、高いほうが霞む。

## それでも変動報酬は要る

純粋な実用ツールは「やらなきゃ」で回すことになり、日記アプリが死ぬ典型パターンに入る。
ただし予測不能性はこの製品に内在している ——「話した内容から何が返ってくるか分からない」。
引くのはユーザーではなくルナで、材料はユーザーが話した内容。話すほど当たりが良くなる。

## 差し替える報酬(既存の演出資産をそのまま使う)

| 新しい報酬 | 中身 | 既存資産の転用先 |
|---|---|---|
| 翌朝の第一声 | 前日の work_items / unresolved_issues から何が拾われるか分からない | 演出なし。会話そのものが報酬 |
| 話題カード | 翌日の会話フックを配る。報酬が次の報告行動に直結する | ガチャ演出・レアリティ表示・コレクショングリッド |
| 週次レビューカード | 「今週のあなた」を1枚。7日話した人だけが開封できる | 開封演出・レアリティの光り方・グリッド |

## 課金から外す理由(きせかえ・アイテムは残すが売らない)

- 一人会社・フリーランス向け実務ツールとしての信用を削る
- 月額課金とガチャ課金は収益の物語が二重になり同居しにくい
- **安全性テスト(angles A2)で出た依存リスクを直接増幅する。**
  愛着を課金対象にするのは「ルナだけが友達」の状態を金銭的に強化する仕組みそのもの。ここは踏まない

きせかえ・アイテムは「買う」ではなく「続けたら変わる」として残す。継続の可視化として機能する。

## 実装順序

ループが閉じる前に報酬設計をやると空回りするため、順番を守る。

1. **DB復旧**(`docs/db-recovery.md`)
2. **ループを一周させる**: 夜に話す → 抽出(work_items) → 翌朝の第一声で一手が返る
3. **ループの計測**: 「夜に話しかけたか」「翌朝の一手を実行したか」。会話品質スコアは指標から外す
4. ここまで動いてから報酬を乗せる:
   - チケット付与条件を「ログイン/日次ボーナス」から「その日のことを話した」に変更
   - ガチャの排出内容を衣装・アイテムから話題カードへ差し替え
   - 週次レビューをカード開封の形で提示
5. NEXT_PUBLIC_SHOW_PLAYFUL を戻し、ガチャ画面を新しい役割で再公開

## やらないこと

- ガチャのコード・演出・グリッドの削除(差し替えて再利用する)
- ガチャ課金、アイテム課金、キャラクター課金
- ループが閉じる前の報酬追加
