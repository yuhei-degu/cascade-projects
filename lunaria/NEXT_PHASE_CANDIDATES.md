## 3. 優先順位 トップ 3（推奨）

### 第 1 位：候補 B（UI コピー v2 適用）

**理由**：
- 下準備完了（MOONBOX_UI_COPY_V2.md にすべて記載）
- 演出体験が**目に見えて**良くなる
- 「ふたを開けるよ」のような世界観表現が画面に出ることで、ユーザーが「Lunaria らしさ」を肌で感じる
- 候補 A が完了済みなので、次に短期で世界観の濃度を上げるならここが自然

→ 次に Codex が着手するなら最有力。

### 第 2 位：候補 D（本番動作確認 + Vercel 環境整備）

**理由**：
- 今までずっと dev でしか動作確認していない。**本番未検証の機能が積み上がっている**のは技術負債
- Phase G〜G++ + 012 が本番で動かなければ、これまでの作業が宙に浮く
- ユーザーが実際に手元で触って楽しめる状態になることでフィードバックループが回る
- 本番特有の問題（タイムアウト・レート制限）を**早く知る**ほどリスク管理が効く

→ 機能追加より**運用基盤の固め**が先。

### 第 3 位：候補 C（月箱コンテンツ v2 実装）

**理由**：
- v1 の反応・演出が固まってきたので、次の「月箱の中身」拡張として自然
- ただし v2 の 4 判断ポイントは、実装前にユーザー判断が必要
- 候補 B と並行しすぎるとガチャ周りの差分が大きくなるので、B 完了後に着手するのが安全

→ B の次、またはユーザー判断が先に済んだ場合の次点。

## 8. 議論したい論点

ユーザーと合意すべき優先度判断：

1. **本番デプロイ（候補 D）を最優先にすべきか、機能追加（候補 A/B）を先にして「綺麗な状態」で本番に出すか**
   - 推奨：A → B を先に当ててから D（綺麗な状態で本番反映が望ましい）
   - 代替：D を先に通して動作保証を取ってから機能追加（堅実派）

2. **候補 E（天井）と候補 F（プロンプト v9）はどちらが優先か**
   - 天井：ガチャ系の運用安全性
   - プロンプト v9：本来のコア機能改善
   - **個人的推奨：F（コア機能優先）**

3. **候補 G（コイン購入）は MVP のままでリリースして OK か、もう少し作り込むか**
   - MVP（色違い派生）でも経済はループする
   - 完全別ライン作成は工数が爆発する

4. **候補 H（Live2D）はユーザーのアート進捗待ち。技術調査だけ先行する？**
   - 並行で技術調査を進めれば、アート完成後の統合がスムーズ
   - ただし調査時間が他作業を圧迫する可能性
