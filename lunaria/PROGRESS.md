## 作成日：2026-04-05

## プロジェクト概要

**サービス名：ルナリア**
**一言定義：「軽いのに逃げない幼なじみAI」**
**最優先目標：「この子を手放したくない」と思わせること**

シン（パーソナルAIコンパニオン）の上位互換として設計。
シンは廃止し、ルナリアに一本化。

## 設計フェーズの成果物

### キャラ設計（確定）
- 幼なじみ系・明るい・ノリ軽め・ちょっと雑
- 最重要ルール：「完璧に説明しないけど、一番ちゃんと向き合ってる」
- 口癖5個・絶対NG表現・トピック別反応を定義済み

### ルーティング設計（確定）
3種類に振り分ける：
- **light_normal**：通常の雑談（Groq Llama）
- **light_probe**：軽く聞き返す（テンプレート固定・LLM不使用）
- **claude_serious**：深い会話（Claude Sonnet）

スコア計算ルール：
- message_score（0/1/2/4/6）
- window_score（直近5発言合計）→ 0〜3:normal / 4〜7:probe / 8以上:serious
- heavy_signal_count ≥ 2 → 強制 claude_serious
- クールダウン：claude_serious 後15分は probe 上限

### 記憶設計（MVP版 3層）
- raw_logs / session / core_memory
- core_memory昇格条件：3セッション以上登場 かつ 感情的重みあり
- 記憶の思い出し方：自然な言及 / 確認 / 沈黙 の3パターン

### 内的目標（lunaria_curiosity）
- 「目標」ではなく「好奇心・育ち」として設計
- ユーザーの関心 → ルナリアが教わる側に立って聞く
- 発火条件：2週間以上トピックが出ていない・light_normal中・セッション1回まで

## 実テストで判明した問題と対処

| 問題 | 対処 | 状態 |
|---|---|---|
| probeフレーズを雑談で多用 | probe基準を明示（「最近」「迷ってる」等のみ） | ✅ 解決 |
| 思考ワードを2個同時使用 | 「1返答に1個まで」をルール化 | ✅ 解決 |
| 勝手な前提を作る（「忙しかったもんね」等） | 禁止事項に明示 | ✅ 解決 |
| 自分の習慣を語る（「最近スイッチ触ってる」） | NG例に追加 | ✅ 解決 |
| 話題の脱線（袋麺→「どこか行く？」） | 「ユーザーの範囲内で返す」をルール化 | ✅ 解決 |
| プロンプトを丸読みする | 「設定を読み上げない」を禁止 | ✅ 解決 |
| 天気・ネットを調べたふりをする | 「調べられない・正直に言う」をルール化 | ✅ 解決 |
| 英語が混入（Hospital等） | 「英語一切使わない」を強化 | ✅ 解決 |
| 性病=性的話題と誤分類 | 健康・病気は「相談」として受け取るよう修正 | ✅ 解決 |
| スラング誤読（粗チン→粗暴） | 「わからない時は聞き返す」を追加 | △ Llamaの限界 |

## ノウハウ蓄積の設計（重要）

「記憶」はユーザー個人への理解。サービス全体のノウハウ蓄積は別で考える必要がある。

### 3層のノウハウ

| 層 | 内容 | 現状 |
|---|---|---|
| ユーザー記憶 | この人の価値観・好み・感情パターン | ✅ 設計済み（core_memory） |
| 会話品質データ | ルーティング誤判定・プロンプトの弱点 | ⚠️ routing_logはあるが未活用 |
| プロンプト改善履歴 | どの修正が何を直したか | ⚠️ このPROGRESS.mdのみ |

### ノウハウを積み上げるサイクル（今やっていること）
1. 実際に会話してログを見る
2. 違和感のある返答を特定する
3. 原因を分析してプロンプトに追記
4. 再テストして確認

→ このサイクルをドキュメント化・仕組み化していくことが「サービス固有のノウハウ」になる
