# 月箱 UI コピー案 v2

作成：2026-04-28
対象：`app/gacha/page.tsx` の演出 / 結果モーダル / 状態表示 / デイリーボーナス
出力：実装ではなく**コピー候補集**。Codex が UI 文言を組む際の引き出し。

設計指針：
- パチンコ的・射幸心煽り表現を徹底排除
- 「ルナリアらしい静かな嬉しさ」を最優先（過剰なテンション・派手な絵文字なし）
- 千束テンポ（明るく速い、媚びない、押しつけない）
- ハズレ感のない、贈り物感のある語彙

---

## 1. 抽選中ステージ文言（10 パターン）

`/gacha` の演出 stage1（運勢色 glow）/ stage2（カットイン）の間に、画面下部にうっすら表示するコピー想定。1〜1.5 秒で読み切れる長さ。

「もしかして…」「キターーー」のような期待値煽りを排除し、ルナが**箱を開けてくれている**穏やかな所作として見せる。

| # | 文言 | 想定タイミング |
|---|---|---|
| 1 | ふたを開けるよ | stage1（開封の合図） |
| 2 | ちょっと待ってね… | stage1（汎用） |
| 3 | 今日のはなんだろう | stage1（軽い好奇心） |
| 4 | ゆっくり開けてみよう | stage1（落ち着き） |
| 5 | 月明かりに、かざして… | stage2（雰囲気） |
| 6 | そっと、覗いてみる | stage2（控えめ） |
| 7 | なに来るかなぁ | stage1（カジュアル） |
| 8 | 静かに、開けるね | stage1（穏やか） |
| 9 | 中身、確かめるね | stage1（淡々） |
| 10 | 今夜の月箱、開ける | stage2（世界観濃） |

**実装ヒント**：
- `production_seed` から決定論的に 1 つ選ぶ → 同じ箱を引き直しても文言が変わらず、世界観が安定する
- ランダムで毎回違う文言にすると「ガチャを連打する楽しみ」が増えて哲学とずれるので非推奨

## 3. チケットなし状態のルナらしい文言（10 個）

現状：「チケットが足りないよ」固定。

これを**ルナのキャラを保ったまま**柔らかく言い換えるバリエーション。重要な制約として「**ハズレ感を出さない**」「**焦らせない**」「**会話に戻る誘導は穏やかに**」。

| # | 文言 |
|---|---|
| 1 | チケット切れちゃったね、ちょっと一息つこ |
| 2 | あー、チケット切らしてるや |
| 3 | ちょっと貯めてからまたね |
| 4 | お喋りしてからまた戻っておいで |
| 5 | 今日のチケットは終わったみたい |
| 6 | はい、続きはまた今度ね |
| 7 | 引けないけど、まあそんな日もある |
| 8 | 会話のあとで、また覗いてみて |
| 9 | ルナと話してるとチケット出るかもよ |
| 10 | 一息ついてからまた来てね |

**実装ヒント**：
- ボタン押下時にトーストで表示（モーダルではなく軽量に）
- ランダムで 1 つ選ぶ
- 9 番「ルナと話してるとチケット出るかもよ」は **会話への自然な誘導** として有用。ただし誘導感を出しすぎないように、頻度は低めに（10 回に 1 回程度）
- 「貯めてから」のような強い指示語は最小限に

## 4. デイリーボーナス受取時の文言（10 個）

「✨ デイリーボーナス（チケット +1）」ボタン押下後に、トーストやインライン表示で出すルナのコメント。

毎日同じ文言だと**ルーチン感**が強くなりすぎるので、ランダムで毎日違う表情を見せる。

| # | 文言 |
|---|---|
| 1 | はい、今日の分のチケット渡しとく |
| 2 | お、来たね。デイリー分どうぞ |
| 3 | 今日のチケット、置いとくね |
| 4 | ちゃんと毎日来るの、えらい |
| 5 | はい、1 枚追加ね |
| 6 | お、忘れずに来たね。今日もよろしく |
| 7 | 今日もありがとう、はいチケット |
| 8 | デイリー分、もらっとこ |
| 9 | 来てくれた。ちゃんと渡すね |
| 10 | これ、今日の分。一日よろしくね |

**実装ヒント**：
- 受取成功時のレスポンスにメッセージを乗せても良いし、クライアント側でランダム選定でも可
- 1〜3 はやや事務的、4〜10 は人間味あり。バランス重視
- 「1 日 1 回ログインしてくれる気持ちへの軽い感謝」を含むものを 2〜3 個入れている（4, 6, 7, 9, 10）
- 「えらい」（4 番）は子ども扱いに聞こえる懸念があるので、頻度は低めにするか様子見

## 5. NG コピー例（「重すぎる」/「煽りすぎる」/「ソシャゲっぽすぎる」）

実装時に避けるべき具体例集。「禁止語彙リスト」ではなく**実際にやりがちな失敗パターン**として列挙。

### 5.1 重すぎる（感情過剰・押しつけがまし）

ルナのキャラ哲学（押しつけない・全肯定しない）と矛盾する。受け手が「重い」と感じた瞬間、関係性が依存的に見える。

| NG 例 | なぜダメか |
|---|---|
| 悠平…これ、本当にあなたへの想いの結晶だよ… | 「想いの結晶」が大袈裟、ルナの自己投影が過剰 |
| ルナ、泣きそう | 感情の重さがガチャ報酬と釣り合わない |
| 永遠に大切にしてね | 永遠は重い。ルナが要求する立場ではない |
| これがあれば、ルナと悠平は一生繋がってる | アイテムを関係性の象徴にすると依存装置化 |
| この気持ち、言葉にできないよ | 言葉にできない感動は、ガチャでは過剰 |
| 悠平にしか渡したくなかったの | 独占的な所有感、千束キャラと矛盾 |

→ 代替：「お、これは特別なやつ」「これ、ちゃんと飾ろう」のように**外形的な評価**で抑える。

### 5.2 煽りすぎる（期待値・FOMO 誘導）

ガチャを引く動機を**ドーパミン操作**にすり替える表現。

| NG 例 | なぜダメか |
|---|---|
| 次は SSR 確定かも！？ | 期待値煽りの典型 |
| もう一回引いたら何が来るかな！？ | 連打誘導 |
| あと少しで天井だよ！ | カウントダウン演出は依存装置 |
| 期間限定！今だけ！ | FOMO（取り残される恐怖）の煽り |
| 他のユーザーも引いてるよ！ | 比較競争で焦らせる |
| 急がないと無くなるよ | 同上 |
| もうこれは引くしかないでしょ | 強制的誘導 |

→ 代替：「お喋りしてからまた戻っておいで」「一息ついてからまた来てね」のように**会話への自然な戻り**で誘導。

### 5.3 ソシャゲっぽすぎる（テンプレ・派手・キャラ崩壊）

業界標準のテンションをそのまま持ち込むと、Lunaria の「静かな贈り物」哲学が崩壊。

| NG 例 | なぜダメか |
|---|---|
| キタァァァ！ / 神引き！ / 天井ぶっ壊した | パチスロ・ソシャゲ用語、世界観破壊 |
| ☆7 確定演出！ / 金虹キター！ | 派手な期待値段階表現 |
| みんなも引こう！ / 拡散希望！ | コミュニティ動員、Lunaria は個人空間 |
| ピックアップ確率 UP 中！ | ソシャゲ運営告知文体 |
| ガチャ運神！ / 引き弱… | 射幸心ワード |
| ご主人様、おめでとうございます | キャラ崩壊（呼称） |
| もう、悠平ったら大胆ですね… | お姉さん媚び（v8 プロンプトで明示禁止） |
| ふふふ、今日は機嫌がいいの | 「ふふ」禁止（v8 プロンプト準拠） |

→ 代替：「お、レアじゃん」「うわ、これはちゃんと飾ろう」のように**ルナ自身の主観**で表現。

### 5.4 ハズレ感（コモン排出時の罠）

「ハズレなし設計」を死守するため、コモンに対するネガ表現は絶対禁止。

| NG 例 | なぜダメか |
|---|---|
| あちゃー、これは… | ガッカリ感 |
| うーん、これかぁ | 露骨な失望 |
| ハズレた… | 「ハズレなし」設計と直接矛盾 |
| コモンかよ | レアリティの優劣で価値判断 |
| もう一回引こうよ | 再ロール誘導は煽り |
| 残念、コモン | 同上 |

→ 代替：「お、ささやかなのが来たね」「これね、なんかほっとするやつ」のように**前向きな受容**。

### 5.5 過剰な絵文字・記号（控えめに）

派手な装飾は世界観を毀損する。

| NG | OK |
|---|---|
| ✨🎉💎🌟🌈 を多用 | ✨ 1 個 / 装飾なしのプレーン |
| !!!! / ！？！？ | !! / ！？ |
| 🎰🎁🎀 のソシャゲ系 | 🎁 を最小限 |

ルナの千束テンポは「！」「笑」程度が上限。「！！！」は使わない。

## 6. 採用ガイド・実装上の注意

### 6.1 文言の選定タイミング

| 場面 | 選定方法 |
|---|---|
| §1 抽選中ステージ | `production_seed` から決定論的に 1 つ選ぶ（同じ引きで再現される） |
| §2 結果見出し | 同上、`production_seed` から決定論的に |
| §3 チケットなし | クリック時にランダム |
| §4 デイリーボーナス | 受取成功時にランダム |

### 6.2 文言の差し替え粒度

- **本ドキュメントは候補集**。実装する Codex は全 10 個全部使う必要なし
- 最初は各カテゴリ 5 個程度を実装し、運用で良し悪しを見て採用入れ替え
- 文言は `lib/lunaria/gacha-copy.ts` のような専用ファイルに集約することを推奨（現状の `gacha-reaction.ts` とは別レイヤー）

### 6.3 多言語化を見据える場合

文言を 1 ファイルに集中しておくと、将来の i18n（en / zh など）対応が容易。今は不要だが、構造の置き場所だけ意識しておく価値あり。

### 6.4 アクセシビリティ

- スクリーンリーダー読み上げを考慮し、絵文字単独の通知は避ける
- 「✨」のような装飾絵文字は読み上げで「キラキラ」と読まれるので、文言と組み合わせる
