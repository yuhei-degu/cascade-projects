## ④ NLP設計

### 使用モデル
- **分類**: `cl-tohoku/bert-base-japanese-whole-word-masking`
  ゼロショット分類でカテゴリ振り分け
- **感情/緊急度**: ルールベース + BERTファインチューン（MVP: ルールベース）
- **キーワード抽出**: TF-IDF + BERT埋め込みの組み合わせ

### カテゴリ定義 (初期16カテゴリ)
```
健康・医療 / お金・投資 / 仕事・副業 / 恋愛・結婚 / 子育て・育児
住宅・不動産 / IT・テック / 法律・手続き / 美容・ダイエット
ペット / 学習・資格 / 旅行・趣味 / 食事・料理 / 人間関係 / 老後・介護 / その他
```

### 処理パイプライン
```
入力テキスト
  → 前処理 (正規化・記号除去)
  → カテゴリ分類 (BERT zero-shot)
  → 金銭ワード検出 (辞書マッチング)
  → 緊急度スコア (ルールベース)
  → 課金意欲検出 (パターンマッチ)
  → テーマクラスタリング (TF-IDF cosine similarity)
```

## ⑤ 競合分析ロジック設計

### 競合強度スコア (0〜100, 低いほど良い)

```python
# 競合強度 = 0.4×search_volume_proxy + 0.3×app_existence + 0.3×ad_density_proxy

# search_volume_proxy:
#   Google Custom Search API の件数を対数正規化
#   APIキーなし時: キーワード出現パターンから推定
#     "〜 アプリ"の検索意図キーワードが含まれる既知アプリ名辞書と照合

# app_existence (0 or 100):
#   known_apps 辞書にテーマキーワードが存在するか
#   (App Store/Google Play カテゴリ情報をDBに事前投入)

# ad_density_proxy:
#   金銭キーワード密度が高いカテゴリ = 広告競合が多い (推定)
#   e.g., "保険","クレジット","ローン" → 広告密度高
```

## ⑥ 収益化可能性スコア設計

### サブスコア構成

| サブスコア | 計算方法 | 重み |
|-----------|---------|------|
| money_word_rate | 金銭ワード出現回数 / 総単語数 | 0.30 |
| urgency_score | 緊急度ワード (今すぐ/助けて/困っている等) | 0.25 |
| payment_intent | 課金意欲ワード (いくら/買いたい/プレミアム等) | 0.25 |
| problem_clarity | 悩みの具体性スコア (TF-IDFの上位キーワード集中度) | 0.20 |

### 金銭ワード辞書
```
高スコア: いくら, 費用, 料金, 払う, 稼ぐ, 儲ける, 節約, 損した
          コスト, 価格, 値段, お金, 収入, 副業, 投資, 節税
中スコア: 安く, 高い, 無料, 有料, 課金, サブスク
低スコア: もったいない, 割引, セール
```

## ⑦ 個人開発難易度推定ロジック

### 推定要素 (各0〜100、高いほど難しい)

| 要素 | 低難易度 (0-33) | 中難易度 (34-66) | 高難易度 (67-100) |
|------|----------------|-----------------|------------------|
| api_dependency | APIなし/公開API | 複数API連携 | プロプライエタリAPI |
| data_dependency | テキスト処理のみ | リアルタイムデータ | 大量データ収集 |
| ai_requirement | ルールベースで可 | 既存モデル使用 | 独自モデル学習 |
| regulation_risk | リスクなし | グレーゾーン | 医療/金融/法律 |

## ⑧ 総合ビジネス指数算出式

```
ビジネス指数 (0〜100) =
  0.4 × 需要スコア (demand_score, 0-100)
+ 0.3 × 収益化可能性スコア (monetize_score, 0-100)
+ 0.2 × (100 - 競合強度スコア) (competitiveness, 100=最低競合)
+ 0.1 × (100 - 開発難易度スコア) (dev_ease, 100=最も簡単)

= 0.4D + 0.3M + 0.2(100-C) + 0.1(100-Dev)
```

### 需要スコア算出
```
raw_demand = log(1 + post_count) × log(1 + avg_comment_count) × growth_rate_factor
  growth_rate_factor = max(0.5, 1 + (posts_this_week - posts_last_week) / max(posts_last_week, 1))
demand_score = min(100, raw_demand × normalization_constant)
```
