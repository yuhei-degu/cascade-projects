# ①②③ 要件定義書 + アーキテクチャ + データ取得設計
# Market Discovery AI — 収益化テーマ発掘エンジン

---

## ① 要件定義書

### 目的
Q&Aサイト・SNS・掲示板の投稿テキストをNLPで解析し、
「需要が高い × 収益化可能 × 競合が弱い × 個人開発可能」
なビジネステーマをスコアリングしてランキング表示する。

### 機能要件

| ID | 機能 | 優先度 |
|----|------|--------|
| F-01 | テキストデータ収集（Reddit API / arXiv / 独自CSVインポート） | High |
| F-02 | カテゴリ自動分類（日本語BERT + ゼロショット分類） | High |
| F-03 | 需要スコア算出（投稿数×コメント数×増加率） | High |
| F-04 | 収益化可能性スコア算出（金銭ワード密度・緊急度・課金意欲） | High |
| F-05 | 競合強度スコア（Google件数代替・既存アプリ有無推定） | High |
| F-06 | 個人開発難易度推定（API依存・規制リスク・AI必要性） | High |
| F-07 | 総合ビジネス指数算出（重み付き加算） | High |
| F-08 | ランキングAPI（フィルター・ソート・ページネーション） | High |
| F-09 | フロントエンド表示（ランキング・詳細・メーター） | High |
| F-10 | バッチ再解析トリガー | Medium |

### 非機能要件

| 項目 | 要件 |
|------|------|
| 個人情報 | 投稿者ID・氏名を保存しない（ハッシュ化または完全削除） |
| 利用規約 | 収集先サイトの利用規約・robots.txt を遵守 |
| スケーラビリティ | Docker → クラウド移行前提 |
| パフォーマンス | ランキング取得 < 300ms（キャッシュ有） |
| セキュリティ | APIキーは環境変数、CORS制限 |

## ③ データ取得設計

### 収集ソース

| ソース | 方法 | 注意事項 |
|--------|------|---------|
| Reddit (r/japanlife, r/startups 等) | Reddit API (PRAW) / Pushshift | API利用規約遵守、レート制限準拠 |
| CSVインポート | 管理者アップロード | Yahoo知恵袋等の公開データ手動収集 |
| 手動入力 | POST /api/v1/posts | テスト・デモ用 |

### 個人情報保護設計
- 投稿者IDは保存前にSHA-256ハッシュ化（再特定不可）
- 投稿本文から個人情報パターン（電話/メール/住所）を正規表現でマスク
- IPアドレスは収集しない

### データフロー
```
外部ソース → RawPost収集 → 個人情報除去 → raw_postsテーブル
                                            ↓
                                    NLPパイプライン
                                    カテゴリ分類 / キーワード抽出
                                            ↓
                                    テーマクラスタリング
                                    (同一悩みグループ化)
                                            ↓
                                    スコア算出 → theme_scores
                                            ↓
                                    ランキングAPI → フロント
```
