## ③ データ取得設計

### 収集フロー
```
[外部ソース] → [Collector] → [前処理] → [個人情報マスキング] → raw_posts
     ↓
robots.txt チェック → ✅ 通過 or ❌ スキップ
レート制限 (3秒間隔) → httpx async client
UA: "MarketDiscoveryAI/1.0 +https://example.com/bot"
```

### データ保存ポリシー（プライバシー）
- 投稿者名・ID: **保存しない**（ハッシュ化も不要 — そもそも取得しない）
- 投稿テキスト: 形態素解析後にキーワード頻度のみ保存
- URL: キャッシュ制御用にのみ保存（ソース追跡のため）
- IPアドレス: 取得しない

### 取得対象フィールド
```json
{
  "source_url": "https://...",    // ドメインのみ
  "category_hint": "健康",        // URLカテゴリから推定
  "title": "質問タイトル",         // 解析後に要約のみ保持
  "body_keywords": ["...", "..."], // 形態素解析済みキーワードのみ
  "comment_count": 15,
  "posted_at": "2026-03-01",
  "source": "yahoo_chiebukuro"
}
```

## ④ NLP設計

### パイプライン
```
投稿テキスト (title + body)
  ↓
① MeCab 形態素解析 → 名詞・動詞・形容詞抽出
  ↓
② ストップワード除去 + 正規化 (半角・全角統一)
  ↓
③ TF-IDF キーワードスコア算出
  ↓
④ 日本語BERT カテゴリ分類 (0-shot or fine-tuned)
  ↓
⑤ 収益化ワード辞書マッチング
  ↓
⑥ 課金意欲スコア算出
  ↓
⑦ テーマクラスタリング (DBSCAN on BERT embeddings)
```

### 使用モデル
- カテゴリ分類: `cl-tohoku/bert-base-japanese-v3` (fine-tuned)
- Embedding: `sbert-large-nlu-ja` (sentence-transformers)
- フォールバック: TF-IDF + キーワードルールベース

### 収益化ワード辞書
```python
MONETIZATION_WORDS = {
    "高緊急": ["すぐに", "急いで", "今すぐ", "緊急", "早急"],
    "課金意欲": ["いくら", "費用", "料金", "払う", "買いたい", "おすすめ教えて"],
    "収益関連": ["稼ぐ", "副業", "収入", "月収", "年収", "投資"],
    "悩み深刻": ["困っている", "助けて", "どうすれば", "解決方法", "アドバイス"],
}
```

## ⑤ 競合分析ロジック設計

### 競合強度スコア算出 (0-100, 低いほど参入余地あり)

```
競合強度 =
  0.50 × 検索量スコア     # SerpAPI or Googleトレンド推定
+ 0.30 × 既存アプリスコア # App Store / Google Play 検索結果数推定
+ 0.20 × 広告出稿スコア   # Google Ads キーワードプランナー推定

検索量スコア:
  Google検索推定結果数 → 対数正規化
  > 10M件 → 100点 (高競合)
  1M-10M → 80点
  100K-1M → 60点
  10K-100K → 40点
  < 10K   → 20点

既存アプリスコア:
  AppStoreキーワード検索 → 該当アプリ数 → 5件超 → 80点, 3-5件 → 60点, 1-2件 → 30点, 0件 → 0点

広告出稿スコア:
  関連キーワードのCPC推定 → 高CPC = 高競合
  > ¥500/click → 80点, ¥100-500 → 50点, < ¥100 → 20点
```

**⚠️ MVPではSerpAPI不使用、キーワード頻度ルールベースで代替**

## ⑥ 収益化可能性スコア設計

```
収益化可能性スコア =
  0.35 × お金ワードスコア     # 料金・費用・稼ぐ系ワード出現率
+ 0.25 × 課金意欲スコア       # 「買いたい」「探している」など購買意図
+ 0.25 × 緊急度スコア         # 「今すぐ」「急いで」など緊急性
+ 0.15 × 問題深刻度スコア     # 「本当に困っている」「どうしても」

お金ワードスコア = min(100, (お金ワード出現数 / 総ワード数) * 5000)
課金意欲スコア = min(100, 課金ワード出現数 * 15)
緊急度スコア = min(100, 緊急ワード出現数 * 20)
問題深刻度スコア = min(100, 深刻ワード出現数 * 12)
```

### ビジネスモデル推定

テーマのキーワード特性から推定収益化モデルを付与:
- B2C SaaS / アプリ課金
- 情報コンテンツ (有料note/教材)
- アフィリエイト
- コンサルティング/相談
- マッチングプラットフォーム

## ⑦ 個人開発難易度推定ロジック

```
開発難易度スコア (0-100, 低いほど簡単) =
  0.30 × API依存スコア         # 必要な外部API数
+ 0.25 × データ量スコア         # 必要なデータ量・取得難易度
+ 0.25 × AI必要性スコア         # ML/AIモデルの必要性
+ 0.20 × 法規制リスクスコア     # 規制・免許リスク

API依存スコア: 必要API数 × 15 (上限100)
データ量スコア: 大量データ必要 → 80, 中 → 50, 小 → 20
AI必要性スコア: コアにAI必要 → 70, 補助的 → 40, 不要 → 10
法規制リスクスコア:
  医療・金融・法律・不動産 → 80 (免許・資格リスク)
  一般 → 20

キーワード→難易度マッピング例:
  "診断" / "処方" / "治療" → 法規制HIGH
  "投資" / "FX" / "保険" → 法規制HIGH
  "予約" / "決済" → API依存HIGH
  "チャット" / "AI" / "音声" → AI必要性HIGH
```
