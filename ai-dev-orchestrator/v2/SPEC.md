# AI Dev Orchestrator v2 — CORE SPEC

## 原点(これが全て)

> アイデアを入れるだけ。AIが 実装 → 検証 → 完成 を回す。
> 目的は「動くプロダクトを出荷する」こと。システムを育てることではない。

対象プロジェクトは **Lunaria ただ1つ**。

## v1の死因(絶対に繰り返さない制約)

v1は done 1 / promoted 35 で死んだ。最終状態のキューは
「ROOTCAUSE-PROMOTE-ROOTCAUSE-PROMOTE-...」という5重ネストの
自己言及メタタスクで埋まり、製品タスクは0件だった。

そこから導く 5つの鉄則:

1. **タスクは人間だけが書く。** AIによるタスク自動生成・自動リスコープ・
   メタタスク(タスクについてのタスク)生成を全面禁止。
2. **状態ファイルは TASKS.md 1つ。** キュー/レビューキュー/判断キュー/
   ステージボード/ダッシュボードは作らない。
3. **1回のrunで1タスク。** 完了しても次のタスクへ自動で進まない。
   人間が diff を見て commit してから次を回す。
4. **修正リトライは1回まで。** 2回目の失敗は `[!]` を付けて停止し、人間に返す。
5. **doneの定義 = 検証コマンドが通ること。** promoted等の中間状態を作らない。

## フロー

```
人間: TASKS.md にタスクを書く (- [ ] ...)
  ↓
python run.py
  ↓ 先頭の [ ] タスクを1つ取り、エージェントCLIに渡す ( [~] に更新)
  ↓ verify_command (build/test) を実行
  成功 → [x] にして停止。人間が git diff を確認して commit。
  失敗 → 修正プロンプトで1回だけ再試行 → なお失敗なら [!] で停止。
```

## 構成(4ファイルで完結)

- SPEC.md      … この文書
- TASKS.md     … 唯一の状態。人間が書き、run.py が記号だけ更新する
- run.py       … ループ本体(~120行)
- config.json  … 対象リポジトリ/エージェントCLI/検証コマンド

## マーク

- `[ ]` 未着手 / `[~]` 実行中 / `[x]` 完了(検証済) / `[!]` 人間の判断待ち
